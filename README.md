# mocap-studio

Mocap Studio is a markerless, video-based motion capture pipeline for filmic
animation in Blender. Seven cameras (4 body, 1 face, 2 hands) film the
actors. Their videos are synchronised, turned into 3D body and hand motion by
neural networks (FreeMoCap / MediaPipe), cleaned up, and imported into
Blender as animation.

**This repository is the organizer.** It holds no mocap logic. It ties the
other repositories together as git submodules and keeps the project-wide
plan, decisions and diagrams.

## Architecture

```
cameras ──live──▶ RECORDER PC ──── rsync, file by file ────▶ PROCESSING PC ──▶ Blender
 UVC (USB)        P1 setup, P2 record (one file per   ──▶    watch: verify each file,
 STREAM (Wi-Fi    camera, host clock), report,               start each step when its
 tablets running  preprocess per role (CPU only),            inputs are in → P3 extract
 the camera app)  hand-off per file ── Harpia ZeroMQ ──▶     (all neural nets) → P4 → P5
```

- **Recorder PC** (Linux): every camera delivers its frames live to it. It
  records one file per camera with every frame stamped on its own clock,
  preprocesses (crop/rescale), and hands each file off as soon as it's ready.
- **Processing PC** (Windows + WSL2, RTX 4080): all neural-net work, then
  clean-up and Blender.
- Repositories never import each other's code. They talk only through
  **`mocap-contracts`** (messages generated by Harpia, plus the session folder
  layout).

Diagrams: [`docs/diagrams/architecture.drawio`](docs/diagrams/architecture.drawio)
(machines, cameras, links) and [`docs/diagrams/pipeline.drawio`](docs/diagrams/pipeline.drawio)
(P1–P5 with every step's inputs and outputs).

## Repositories

| Repository | Runs on | Pipeline stage | What it does |
|---|---|---|---|
| [`mocap-contracts`](mocap-contracts) | everywhere (library) | all | `.harpia` messages → generated Python/Java, JSON helpers, rules, session folder layout |
| [`mocap-capture`](mocap-capture) | recorder PC | P1 setup, P2 capture | cameras, camera controls, recording, sync markers, take report, preprocessing, hand-off |
| [`mocap-camera-app`](mocap-camera-app) | tablets/phones (Android) | P2 | turns a device into a STREAM camera for the recorder |
| [`mocap-extract`](mocap-extract) | processing PC | P3 extract | alignment, calibration, FreeMoCap body + hands, per-camera quality |
| [`mocap-adapt`](mocap-adapt) | processing PC | P4 adapt | one timeline, smoothing, feet on the floor → `MocapTake` |
| [`mocap-blender`](mocap-blender) | processing PC (Blender) | P5 Blender | Blender add-on: animated empties, NLA layers |
| [`mocap-sync-fw`](mocap-sync-fw) | ESP32 | — | LED flash sync firmware, **parked** |

Clone with `git clone --recurse-submodules`, or run `git submodule update --init`
after cloning.

## How work is organized

Every repository plans its work as initiative → epic → task under
`initiatives/`, with one git branch per level. The rules are in the
`mocap-workflow` skill (`.claude/skills/mocap-workflow/SKILL.md`), which is
copied into every repository. `main` is the release branch used for real
capture sessions, and `dev` is the development branch.
